# AI PM 工程能力比较矩阵

更新日期：2026-08-09

状态：已完成

## 评分说明

- 5：高度匹配，可优先验证
- 4：匹配度较高，有明确限制
- 3：部分适合，主要借鉴或作为备选
- 2：当前阶段偏重或偏离目标
- 1：不建议进入当前方案

## 当前争议点

| 问题 | 方案 A | 方案 B | 当前裁决 |
|---|---|---|---|
| 飞书内任务真源 | 多维表格直接做真源 | 自有领域层，表格只做投影 | 选择 B；复杂来源、纠错和可见性无法只靠表格可靠表达 |
| 朋友试点租户 | 跨租户商店应用 | 同一专用租户自建应用 | 先选择 B；跨租户作为后续独立阶段 |
| 独立任务系统 | 直接采用 Plane | 先使用飞书原生投影 | 先原生；出现界面和权限瓶颈后验证 Plane |
| 长期记忆 | 直接部署 Mem0 | 先用原始事件库和结构化检索 | 先基础检索；证明召回不足后再加 Mem0 |
| 流程引擎 | 立即使用 LangGraph/Temporal | 先简单事件处理 | 先简单；出现长流程恢复和复杂重试后升级 |
| 首期可靠性 | 进程内队列和定时器 | PostgreSQL inbox/job/outbox | 选择 B；需要幂等、重试、死信和对账 |
| 个人私聊触发 | CLI/WebSocket 实时事件 | 用户 OAuth 周期查询 + 重叠窗口去重 | 选择 B；应用事件流不能覆盖用户全部人际私聊 |
| n8n定位 | 核心任务编排 | 外围SaaS集成 | 选择 B；核心状态必须回写领域真源 |
| 文件完成判断 | 根据文件变化自动完成 | 文件只作为活动和候选产物信号 | 选择 B，正式完成必须由人确认 |

## 实施前待验证

- 飞书全部私聊与原文长期留存的权限和组织政策；
- 实际月 API 额度、调用成本和断线补漏；
- 同一专用租户朋友试点是否可接受；
- 本地只读桥接器的目录授权、安全更新和多平台维护。
