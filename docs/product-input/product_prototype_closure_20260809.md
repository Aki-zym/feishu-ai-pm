# 飞书个人 AI 数据 PM：产品行为原型阶段收口

记录日期：2026-08-09

## 一句话结论

这是一个在后台持续工作的个人 AI 数据 PM：它从授权的飞书对话、会议和本地任务目录中维护完整任务记忆，通过机器人私下提醒用户，并由用户掌握所有对外可见动作和正式承诺。

当前产品行为已经形成闭环。本项目继续只承担设计与资料研究，不进入编码、接入或部署。

## 产品本体与三个载体

- **产品本体**：个人工单台账与可回溯工作记忆。
- **机器人**：候选需求提醒、每日摘要、查询、确认和人工补录入口。
- **原始私聊或群聊**：默认协作空间；不要求需求方改变原有沟通习惯。
- **新建需求群**：只有多人需要共同确认、上下文分散或需要持续协作时才按需创建。

机器人和需求群都不是产品成立的前提。

## 完整主链

```text
授权私聊 / 指定群聊 / 会后内容 / 机器人补录
                    ↓
            AI 静默识别与关联
                    ↓
        新候选立即由机器人私下提醒
                    ↓
             接受 / 暂存 / 忽略
                    ↓
        私人正式台账与上下文持续更新
                    ↓
       日历排期、文件活动和风险自动感知
                    ↓
          用户确认对外动作与正式完成
                    ↓
          原文、describe、产物位置可召回
```

### 不同入口

- 需求方直接私聊用户：AI 静默判断，不在原私聊中自动发言。
- 需求方私聊机器人：机器人可在事前授权范围内澄清背景、数据验证原因和希望支持的判断。
- 指定群聊：出现新消息后判断一次，与新需求或已有任务有关才记录。
- 会议：会后从允许读取的纪要、转写或原文中识别事项。
- 人工补录：用户转发消息给机器人，或明确说“把这条记成任务”。

## 自动化与人的边界

### AI 在私人空间自动完成

- 识别需求、背景、任务变化和文件活动；
- 关联已有任务、新建候选、合并、去重或忽略；
- 更新 `describe`、原始来源、上下文时间线和风险；
- 根据工单负载与日历提出执行时间和交付日期建议；
- 根据 reference path 读取授权工作目录的文件清单、变化和产物位置。

### 必须由用户决定

- 接受、暂存或忽略候选需求；
- 任何其他人可见的回复、共享、拉群、邀请、排期或状态；
- 正式负责人、范围、优先级和对外交付时间；
- 任务是否已正式完成。

统一门禁只有一句话：**只要系统主人以外的人能够看到，就是对外动作。**

## 任务记忆

任务同时维护两层信息：

- **来源层**：在授权和合规允许范围内保留完整原始聊天及其他来源，用于追溯和重新总结。
- **使用层**：日常只展示简洁 `describe`、当前结论、角色、状态、时间、下一步和风险。

当 `describe` 无法回答问题时，AI 回查来源层，再生成针对当前问题的总结。原始聊天的真实读取、长期留存、权限和组织合规边界仍需依据飞书官方能力核验。

## 纠错与持续升级

用户可以一键指出任务关联、角色、拆分、合并或其他判断错误。纠错链路为：

```text
立即修正当前任务
    → 保存错误案例与正确结果
    → 形成个人规则或示例
    → 汇总评测共性问题
    → 审核后升级提示词或机制
    → 支持版本回退
```

个人纠错默认只影响本人的 PM。只有经过汇总、评测和审核的抽象规则才能进入全局能力，不能跨用户复用私聊原文。

## 跟进、日历与完成

- 机器人每天发送一次低密度摘要，聚焦今天要处理、临期、等待他人和待确认完成的任务。
- 普通进展静默写入；新需求、范围或承诺变化、延期风险和疑似交付才额外提醒。
- 工单管理“做什么”，日历管理“什么时候做”。AI 可以建议专注时间和交付日期，但用户确认后才生效。
- 出现文件或“最终版”表达只能生成候选交付状态；用户确认后才正式完成。

## Agent 工作区 reference path

系统可以在用户指定位置生成本地任务目录。任务目录只保存：

- `task_id`；
- 任务说明与必要索引；
- 一个或多个实际工作目录的 `reference path`；
- 文件清单、最近变化和可能的产物位置。

任务目录可以由系统创建、读取和写入。关联的实际工作目录只按用户授权读取；系统不复制归档、不写入、不移动、不覆盖、不删除真实工作文件。路径失效时只提示重新关联。

这是一项底层接口要求，不继续在当前原型中设计主工作区、辅助工作区或具体目录实现。

## 当前不再继续细化的内容

- 不再模拟 LLM 对简单任务查询的回答；当前假设是明确提示词与充分上下文足以完成这些基础判断。
- 不进入页面排列、视觉样式或可运行 Demo。
- 不选择具体数据库、框架、文件监听器或 Agent 适配实现。
- 不真实调用飞书 CLI、API、Hook、SDK 或 MCP。

## 下一阶段

后续由用户另行开启目标任务，前往官方文档、产品网站和 GitHub 寻找成熟工程方案，重点研究：

1. 飞书授权私聊、群聊、会议、日历和文件的读取与事件能力；
2. 完整聊天留存的权限、组织政策、安全和成本；
3. 成熟任务系统、个人 AI 助手和工作记忆架构；
4. 本地任务目录、reference path、文件变化监听与 Agent 工作区适配方式；
5. 可版本化、可评测、可回退的提示词与纠错学习机制。

该研究仍属于本设计项目；如果决定制作软件，应另建实施项目。
