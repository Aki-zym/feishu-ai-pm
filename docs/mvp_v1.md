# 历史首版 MVP 合同（M0a / M0b）

> 本文件保留首版历史范围，不再回答当前阶段。当前实现、安装包和验证状态只查 [当前状态](current-state.md)；后续用户可见演进查 [CHANGELOG](../CHANGELOG.md)。

## 当时的可运行空壳（M0a）

本仓库已先完成不连接真实飞书的 M0a：使用显式测试装配中的虚拟消息夹具验证来源保存、`message_id` 去重、候选接受/暂存/忽略、正式任务台账、私人网页、对外动作待确认和本地删除数据库文件的能力。

下文涉及真实自建应用、用户 OAuth、消息权限、模型调用和线上删除导出的条目仍属于 M0b 飞书 PoC，不应因为本地空壳可运行而视为已验证。

## 首版目标

证明“消息来源 -> 候选工单 -> 人工确认 -> 私人任务台账”能够可靠闭环。首版不追求完整页面、跨租户产品化或复杂长期记忆。

## 必须实现

1. 使用一个专用飞书自建应用完成系统主人授权。
2. 机器人收到一条私聊消息后，能够写入耐久来源记录。
3. 若权限允许，用户身份能够分页发现既有 P2P，以对方 `open_id` 标识；新发现人员默认不关注，主人选择后才读取新消息。本条不代表应用能读取飞书 API 未返回的全部普通私聊，也不代表实时推送。
4. 同一 `message_id` 重复进入时不会重复建立来源或候选。
5. AI 能识别“可能的数据需求”，生成提出人、背景、希望验证的问题和简洁 `describe`。
6. 系统主人能够接受、暂存或忽略候选。
7. 接受后的任务能够在私人网页中查看，并回查原始来源。
8. 所有对外可见动作都停留在“待确认”，不会自动发出。
9. 能按隐私流程永久删除试点用户的原文、派生摘要和任务数据；这与日常任务回收站的可恢复软删除不同。

## 暂不实现

- 自动执行任何任务。
- 自动拉群、回复、排期或宣布完成。
- 全公司、跨租户或应用商店发布。
- 全量会议、文档和本地文件监听；本条描述的是 M0/M0b 的历史范围，不限制当前 M1 个人信息流主链。当前日历和会议纪要自动增量已在独立里程碑实现，仍需真实租户验收；这些扩展不改变本首版 MVP 的历史范围。
- Mem0、Graphiti、Temporal、复杂 Agent 工作流。
- 完整手机端、甘特图或团队项目管理。

## 验收场景

```text
需求方发出一条数据需求
  -> 系统只保存一次原始来源
  -> 私下提醒系统主人有新候选
  -> 系统主人点击接受
  -> 私人任务页出现任务、提出人和 describe
  -> 原聊天中没有自动回复
```

发生断网、分页失败或重复投递时，系统必须能够重试或对账，且不能静默漏记或重复建单。

## 后续演进

M1 之后的能力不回填为本历史合同的“当前状态”。请从 [当前状态](current-state.md) 进入，并在 [CHANGELOG](../CHANGELOG.md) 查看用户可见历史。首版第 9 项的隐私硬删除目标仍是开放问题，不能用日常软删除替代。
