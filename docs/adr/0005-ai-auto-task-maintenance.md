# 0005：AI 自动维护私人任务，主人事后监督

## 问题

ADR 0004 建立了受控 Runtime、需求线程和任务更新提案，并要求所有提案由系统主人逐条批准。该方式安全，但同一需求持续补充时会产生大量重复审批，私人任务台账不能及时反映明确的新事实。

## 备选方案

1. 继续要求每条更新事前批准。
2. 让模型自由修改任务、执行工具或对外发送。
3. 只允许证据充分的私人内部更新自动应用，其他情况安全降级为待确认，并提供暂停、审计、撤销和人工纠正。

## 最终决定

选择方案 3。本 ADR 部分取代 ADR 0004 中“任务更新提案必须全部由主人批准后才写入”的决定；ADR 0004 的耐久来源、Runtime、版本检查、Tool Registry 和任务记忆边界继续有效。

- 自动应用必须同时满足：归属唯一；回复链、明确会话或主人已确认归属等强证据；模型未降级；关联和字段更新置信度达到安全阈值；任务与线程版本一致；全局处于自动模式；任务未暂停；计划时间不是待确认推测。
- 自动修改只覆盖私人 PM 白名单字段：需求线程内容，以及任务标题、Describe、下一步、风险、等待原因、内部状态和私人计划时间。
- `completed` / `archived` 需要来源明确表达完成、取消或不再处理，并重点提示主人；文件出现、聊天中的“最终版”或模型猜测不构成完成证据。
- 歧义、弱关联、模型异常、版本冲突、推测时间、全局仅建议或单任务暂停时，来源和提案仍然耐久保存，但进入待确认。
- 每次自动修改保存应用前后值、来源、模型、prompt 版本、关联/更新置信度、原因、策略版本和任务事件。只要该修改仍是任务最新版本，主人可以撤销；存在后续修改时必须拒绝覆盖。
- 自动应用成功后只保留自动修改提醒；安全门未通过时只保留待确认提醒。同一来源不得同时留下两类未读提醒，工作台“需要关注”是统一监督入口。
- 主人可完整编辑任务、暂停或恢复单任务自动维护，并清理重建任务记忆。人工纠正和撤销作为新的审计事实追加，不能改写原 AI 事件。
- SQLite 是任务、来源和审计的唯一事实真源；任务记忆目录只承担可重建投影，不得反向覆盖 SQLite。
- 自动化不发送消息、不作对外排期或完成承诺、不执行任务或任意 SQL/Shell、不删除任务、不判定“这不是需求”、不物理清除 SQLite 数据，也不修改真实工作目录。

## 原因

私人任务台账需要及时吸收明确的持续对话，同时必须把模型错误限制在可见、可恢复的内部记录范围。双重置信度、强证据和版本门禁降低误关联与静默覆盖；事后通知、撤销和人工编辑让主人保留最终控制权。

## 限制与重新评估条件

- 当前阈值和证据规则是安全默认值，仍需通过真实租户持续消息样本验证误关联率。
- 连续消息当前只在同一会话的一次完整分页扫描批次内合并；跨轮询延迟聚合和实时 WebSocket 多消息缓冲尚未实现。未来若增加缓冲，必须继续逐条保存原始来源，并定义等待窗口、重启恢复和重复判断边界。
- 当前只自动修改本机私人 PM；若未来要自动外发、执行任务、删除数据或修改真实文件，必须新建 ADR，并继续要求主人事前确认。
- 若多设备并发、跨服务 Worker 或更复杂补偿导致本地版本门不足，再评估分布式工作流和更强一致性机制。
