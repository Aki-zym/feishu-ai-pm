# ADR 0002：个人信息流优先，机器人降级为补充入口

- 状态：已决定
- 日期：2026-08-10
- 2026-08-11 修订：个人 P2P 改为自动发现，群聊仍明确选择，机器人群与主人信息流拆分。
- 2026-08-14 修订：新发现个人默认不关注；主人可逐个选择或一键关注当前已发现人员，以后新发现人员仍保持关闭。

## 背景

需求方通常直接联系系统主人，而不是主动与机器人对话。如果系统只依赖机器人私聊和机器人所在群，就会漏掉主人普通私聊、群聊中 `@主人`、日历和会议纪要。

## 决定

正式主链改为：

```text
系统主人 OAuth
├─ 既有 P2P 会话：自动发现并保存 open_id，默认关闭、主人选择
│  └─ 缓存或解析 P2P chat_id，周期读取对方新来信
├─ 主人所在群列表：主人按群名选择
│  └─ 分页读取后只持久化真实 @主人
├─ 个人日历增量同步
└─ 妙记搜索与生成事件
          ↓
       耐久 inbox
          ↓
      AI 判断与候选
```

机器人只承担：

- 需求方直接私聊机器人的补充入口；
- 明确授权重点群的实时消息；
- 平台不可读场景的转发和人工补录；
- 经系统主人确认后的私人提醒或外发动作。

飞书企业自建应用仍然必须存在，用于 OAuth、API 权限、Token 管理和事件连接；但不要求需求方把机器人当成主要交互对象。

## 官方能力边界

| 来源 | 正式方式 | 实时性 | 主要限制 |
| --- | --- | --- | --- |
| 主人普通私聊 | `types=p2p` 分页发现 → 默认关闭、主人选择 → `message.list` | 周期扫描 | 不做实时推送；只覆盖主人 OAuth 实际返回、主人关注且可读取的既有会话 |
| 群聊 `@主人` | 群列表发现 → 主人按群名选择 → `message.list` → 本地匹配 mentions | 周期扫描 + 补充事件 | 只覆盖明确选择群；主人用户身份主链不要求机器人在群内 |
| 新加入群 | 用户身份 `GET /im/v1/chats` 比较 `chat_id` | 周期扫描 | 只登记发现与可读状态，不自动读取新群正文 |
| 日历 | 用户身份列表与 `sync_token` 增量 | 增量 + 事件唤醒 | 事件不是最终状态真源 |
| 妙记 | 用户身份搜索、生成事件和转写导出 | 增量 + 事件唤醒 | 单篇访问权、完成状态和导出权限 |
| 机器人补充 | `im.message.receive_v1` | 实时 | 只覆盖应用/机器人可见范围 |

正式合同以飞书开放平台文档为准：

- [搜索消息](https://open.feishu.cn/document/server-docs/search-v2/message/search-messages)
- [获取会话历史消息](https://open.feishu.cn/document/server-docs/im-v1/message/list)
- [接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)
- [获取用户或机器人所在群列表](https://open.feishu.cn/document/server-docs/group/chat/list)
- [获取用户信息](https://open.feishu.cn/document/server-docs/authentication-management/login-state-management/get)

`lark-cli` 只作为官方实现参考：其 `--as user --types=p2p`、联系人搜索、`chat_p2p/batch_query` 和消息分页链验证了用户身份下的选择式 P2P 读取方式；EXE 仍直接使用开放平台 API 和官方 Node SDK，不启动 CLI 常驻进程。CLI 与正式 API 返回冲突时，以目标租户实际响应和更保守边界为准。

## 安全结果

- 新发现个人 P2P 和新群都默认关闭；主人可逐个关注人员或一键关注当前名单，以后新发现人员不会自动加入。
- 个人单聊只读取主人 OAuth 实际返回的既有会话；群聊只读取主人明确选择群并保留真实 `@主人`。无法解析或无权限时显示受限，并提供机器人私聊、转发和人工补录降级。
- 不可读取的范围显示为受限或不支持，不能伪造全量监控。
- 所有来源只形成私人候选；外人可见动作继续进入 Outbox。
- 日历、文件和会议只能提供线索，不能自动承诺排期或判断任务完成。

## 当前实施状态

当前实现与本 ADR 的读取边界保持一致；本节不构成真实租户或 L6 验证。

## 重新评估条件

当目标租户权限、API 返回范围或真实试点规模发生变化时，重新评估读取边界并新增 ADR；不得通过实现默认扩大读取范围。

代码已实现 `P2P 分页发现 → 默认关闭 / 主人选择或关注当前全部 → message.list`，以及 `群列表 → 主人选择群 → message.list → 本地 mentions 匹配`。人员和群分别保存独立游标；已有选择刷新后保留，重新启用不补未关注期间历史，超过 50 个已关注私聊时采用有界轮转并显示部分状态。主人自己发送的 P2P 不建普通候选，单目标失败不阻塞其他目标。无凭证契约测试已覆盖默认关闭、批量关注当前名单、P2P 解析、取消与重启用、群 mentions、分页、重叠窗口、去重、Token 刷新、限流重试、主人切换和不产生 Outbox。真实租户的 P2P/群历史范围、列表排序和管理员审批仍待验收。
