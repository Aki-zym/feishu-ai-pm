## DEC-01 已确认

SQLite、draft-only、上海自然日与日历候选边界、PR/独立复核治理、分阶段隐私删除、真实试点门禁和产品最高边界均已由负责人确认；详情、影响、依赖和未验证 L5/L6 见 [DEC-01 决策登记](decision-register.md)。

Issue #64 记录但不实现的当前差距：source_event 尚无 append-only revision/history；candidate ignored 仍可由 classifier 路径产生且可恢复；task archived、job cancelled 仍可恢复；outbox ready/sent 没有当前发送路径；#58 四态 outcome/readiness/operation identity 仍是独立 Draft PR 的未来接口依赖。

以下事项会改变实施路径，决定前不要让多人分别采用不同方案。

## P1：个人信息流主链与真实验证

- [x] 确认产品架构采用“用户 OAuth 个人信息流为主、机器人为补充”：见 ADR 0002。
- [x] 已纠正消息能力边界：消息搜索不能用空关键词扫描；主人 OAuth 分页发现既有 P2P，但默认不关注，主人选择后才读取；群聊按群名选择并只处理真实 `@主人`。
- [ ] 验证目标租户是否批准联系人搜索、P2P/群消息用户身份读取、日历和妙记权限。
- [ ] 验证目标租户是否批准 `docx:document:readonly`、`wiki:node:read`，以及 Docx/Wiki→Docx 的实际可读范围、revision、撤权和临时失败表现。
- [ ] 验证主人 OAuth 自动发现 P2P 的覆盖、返回顺序、消息历史、自己/对方发送者区分、分页范围和超过 50 人时的轮转延迟。
- [ ] 验证明确选择群在主人用户身份下的历史读取、mentions 和分页范围；该主链不依赖机器人入群。
- [ ] 测量周期查询延迟、调用量和 API 限流。
- [ ] 验证撤回、删除、离群和授权撤销后的消息表现。
- [ ] 验证断网、第二页失败、重复消息和令牌失效的补漏能力。
- [ ] 在真实租户验证疑似补充消息的 72 小时/3 页有界背景补扫：硬起点、权限不足、分页截断、限流和不推进正常游标的表现。
- [ ] 用真实密集对话验证多需求拆分和已有任务关联：一条消息同时涉及两个需求、话题交错、漏掉首条消息和后续纠错均不能串改另一需求。
- [ ] 决定原文加密、面向隐私/导出的长期备份策略和跨设备恢复方式；Issue #34 只建立本机受管导出、备份校验、硬删除证明和失败回滚合同。
